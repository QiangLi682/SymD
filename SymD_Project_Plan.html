01 — Overview

What We're Building

This project is a web app that takes music written in standard Western notation and converts it into SymD (Symmetric Dodecaphonic Harmony) notation — a modern system patented by Yaodong Chen in 2025.

Instead of note names like C, D#, or Bb, SymD uses interval numbers 0–11 measured from a tonic, arranged on a symmetrical 5-line staff centered on the tritone (interval 6). The result makes harmonic relationships visually explicit with no key signatures or accidentals needed.

Why this matters

Standard notation was designed in the 17th century for tonal, diatonic music. SymD works equally well for tonal, atonal, and chromatic music — and makes intervallic harmony visible at a glance. It's especially powerful for music theory education and analysis.

Project Goals

  • Accept music in ABC notation, MusicXML, and audio (MP3/WAV) formats
  • Convert to SymD interval numbers with correct key detection
  • Render a proper SymD staff visually in the browser (SVG)
  • Allow export to SVG and PDF
  • Provide an educational reference panel explaining the SymD system
02 — Architecture

System Design

Three layers, deliberately separated so each can be built and tested independently.

Layer Responsibility Technology
Input Parser Read music from ABC, MusicXML, or audio files Python / music21 / basic-pitch
Conversion Engine Map every note to a SymD interval number (0–11) Python — pure logic
SymD Renderer Draw the asymmetric 5-line staff and place notes React + SVG
App Shell File upload, key selector, export controls React + FastAPI

Data Flow

  • User uploads a file or pastes ABC text into the browser
  • Backend parser extracts a list of notes with durations and timestamps
  • Conversion engine maps each note to its SymD interval (0–11) from the tonic
  • Interval + rhythm data sent to the React frontend as JSON
  • SVG renderer draws the SymD staff and places note heads at correct positions
  • User can export the result or adjust the key and re-render
03 — Phases

Development Phases

1
Core Conversion Engine
1–2 days  ·  Build the math first, no UI

This is the heart of the whole system. Get it right before touching anything else.

  • Implement semitone mapping: C=0, C#/D♭=1, D=2 … B=11
  • Given a tonic, calculate each note's interval (semitones from tonic, mod 12)
  • Map each interval to its SymD staff position (one of 13 locations)
  • Handle enharmonic equivalents (F# and G♭ → same position)
  • Write unit tests for every interval mapping
First Milestone

Input: hardcoded note list + tonic. Output: printed list of SymD interval numbers. When this works, the core logic is proven.

2
Input Parsers
1–2 weeks  ·  Build in order: ABC → MusicXML → Audio

Add the ability to read real music files.

3
SymD Staff Renderer
1 week  ·  Draw the custom staff in SVG

This is what makes the app visually unique. Build it as a standalone React component accepting a JSON array of notes.

  • Draw 5 lines with the correct asymmetric spacing (outer gaps wider than inner)
  • Bold the center line (Line 3 = tritone, interval 6)
  • Optionally shade mediant spaces (intervals 3 & 9, per patent Fig. 8)
  • Map each interval number to the correct vertical pixel position
  • Place note heads along the time axis proportional to duration
  • Stack multiple notes at same time vertically (chords)
  • Display interval numbers alongside note heads
4
App Shell & UI
1–2 weeks  ·  Wrap the engine in a usable interface
  • Drag-and-drop file upload (ABC, MusicXML, MP3, WAV)
  • ABC text input box for direct paste
  • Key selector — which pitch is interval 0?
  • Toggle: auto key detection vs. manual key
  • SymD staff display with zoom and scroll
  • Side panel: interval reference table
  • Export: SVG download, PDF download
5
Polish & Education Features
1 week  ·  Make it a learning tool
  • Highlight harmonic regions (dominant, subdominant, leading tones)
  • Hover a note to see its interval name, traditional name, and solfege
  • Side-by-side comparison: traditional notation vs. SymD
  • Embedded tutorial explaining the SymD system for new users
04 — Tech Stack

Recommended Technologies

Frontend React + SVG SVG is ideal for drawing custom staves with precise coordinates. React manages state for key selection and re-rendering.
Styling Tailwind CSS Fast to prototype, responsive by default. No custom CSS config needed.
Backend API Python + FastAPI music21 runs in Python. FastAPI is lightweight, fast, and pairs well with React frontends.
Music Parsing music21 Industry-standard Python library for music analysis. Handles ABC, MusicXML, key detection, chords, and durations.
Audio Transcription Spotify basic-pitch Best open-source automatic music transcription model. Converts MP3/WAV to MIDI note events.
PDF Export jsPDF or Puppeteer Convert the rendered SVG to a downloadable PDF. jsPDF runs in the browser; Puppeteer runs server-side.

05 — Challenges

Key Challenges & Solutions

Key Detection

If the input doesn't specify a key, you must infer it. music21 includes Krumhansl-Schmuckler key detection — it works well but isn't perfect. Always let users override the detected key.

Rhythm Preservation

SymD only changes pitch representation, not rhythm. Preserve note durations, ties, beams, and time signatures exactly. music21 handles this automatically when parsing files.

Polyphony (Chords)

Multiple notes at the same time must stack vertically on the SymD staff. Your data model must group simultaneous notes, and the renderer must handle vertical stacking.

Audio Transcription Accuracy

MP3/WAV pitch detection is imperfect, especially for chords and fast passages. Set clear user expectations and add a note editor so users can fix errors before converting.

Staff Spacing Fidelity

The patent specifies precise proportions — outer gaps should be 1.5–3× wider than inner gaps. Get the proportions right early; they affect readability of harmonic relationships.

Enharmonic Equivalents

F# and G♭ are the same SymD position but different traditional notes. Your semitone mapping must normalize these before converting, then optionally display the original spelling.

07 — Where to Start

Your First Coding Session

Don't start with the UI. Start with the logic. Here is a concrete first session plan:

  • Install Python and music21: pip install music21
  • Write a function: note name + tonic → SymD interval number (e.g. G in C = 7)
  • Write a function: interval number → SymD staff position (0–12)
  • Load a simple ABC tune with music21 and print each note's SymD interval
# Example — what you're aiming for at the end of Day 1 from music21 import converter, pitch def note_to_symd(note_name, tonic_name): note_pitch = pitch.Pitch(note_name) tonic_pitch = pitch.Pitch(tonic_name) semitones = (note_pitch.midi - tonic_pitch.midi) % 12 return semitones # 0–11, the SymD interval # Test it print(note_to_symd('G', 'C')) # → 7 (perfect fifth) print(note_to_symd('F#', 'C')) # → 6 (tritone) print(note_to_symd('Bb', 'C')) # → 10 (minor seventh)
Start small, win fast

A working command-line ABC → SymD interval list in 2 days beats 2 weeks building UI infrastructure around untested logic. Get M1 done first — everything else builds on it.
